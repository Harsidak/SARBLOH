\section{Preliminaries and Related Work}
\label{sec:prelim}

\subsection{Environment}
\label{sec:env}
An ARC-AGI-3 environment \citep{arcagi3} is an uninstructed, discrete-time game made of an ordered sequence of levels $\{1, \dots, n\}$. At each step $t$ the agent sees a frame $g_t \in \{0, \dots, 15\}^{H \times W}$ with $H, W \le 64$, the episode state $s_t \in \{\code{NOT\_FINISHED}, \code{WIN}, \code{GAME\_OVER}\}$ and the number of levels cleared. It then picks an action from
\begin{equation}
\begin{split}\mathcal{A} = \{&\code{ACTION1}, \dots, \code{ACTION5},\\ &\code{ACTION6}(x,y), \code{ACTION7}, \code{RESET}\},\end{split}
\end{equation}
where \code{ACTION1}--\code{ACTION4} are directional, \code{ACTION5} and \code{ACTION7} are game-specific, and \code{ACTION6}$(x,y)$ is a click at pixel $(x,y)$. Nothing is explained up front: what the actions do, which object the agent controls and what wins the level must all be inferred from transitions. Early levels introduce single mechanics and later levels compose them \citep{spelke2007core}.

Games are scored by \emph{Relative Human Action Efficiency} (RHAE). Let $h_l$ be the human baseline for level $l$ (the upper-median human action count) and $a_l$ the agent's action count. Then
\begin{equation}
\begin{split}
S_l &= \min\!\left(1.15,\, \left(\frac{h_l}{a_l}\right)^2\right),\\
E &= \frac{\min\!\left(\sum_{l=1}^k l,\; \sum_{l=1}^n l\, S_l\right)}{\sum_{l=1}^n l},
\end{split}
\label{eq:rhae}
\end{equation}
where $k \le n$ is the number of levels cleared, and the benchmark score is the mean of $E$ over games. Three consequences drive our design. Extra actions are penalized quadratically, so an agent that needs twice the human count keeps only 25\% of the credit. Thinking and host-side computation are free, and only actions sent to the environment count in $a_l$, which favours planning in code over trial and error. And the weight $l$ pushes the score toward later levels.

\paragraph{Offline evaluation and resource bounds.}
The official Kaggle track runs a submitted notebook on held-out games with no network access. It gets one NVIDIA RTX PRO 6000 (Blackwell, 96\,GB VRAM), 176\,GB of host RAM and a nine-hour wall-clock limit for the whole suite, and all weights must be open and packaged with the notebook. The budget is therefore decode throughput, since reasoning is bounded by tokens per second, and the length of prompt that can stay in the warm prefix cache without eviction or recomputation.

\subsection{Related Work}
\label{sec:related}

\paragraph{Static Inductive Program Synthesis.} 
Early static ARC benchmarks \citep{chollet2019measure} were dominated by symbolic search over expressive, hand-crafted Domain-Specific Languages (DSLs) \citep{wind2020icecuber}. Subsequent research expanded symbolic synthesis through abstract reasoning graph architectures \citep{xu2023arga}, hierarchical library learning \citep{ellis2021dreamcoder}, and Minimum Description Length (MDL) inductive biases \citep{ferre2025madil}. In the ARC Prize 2024 competition, state-of-the-art approaches transitioned toward neural synthesis: test-time training (TTT) on augmented task instances \citep{akyurek2024ttt,arcprize2024}, unified inductive-transductive program induction \citep{li2024induction}, and ultra-compact recursive neural architectures \citep{jolicoeur2025trm}. However, these static methodologies are fundamentally transductive: they map small sets of paired input-output demonstration grids to a single static solution grid, operating entirely without interactive environmental feedback or sequential action execution.

\paragraph{Interactive Agents and World Models.} 
Interactive abstract reasoning demands an entirely distinct agentic paradigm. General large language model agents typically interleave textual reasoning and tool execution \citep{yao2022react} or incrementally construct modular libraries of executable code skills \citep{wang2023voyager}. In the context of ARC-AGI-3, several frontier systems have emerged. \emph{Prime Agent} \citep{karten2026prime} equips a frontier model with a persistent IPython REPL; our initial agent harness originated as an open-weight port of this execution loop. \emph{Executable World Models} \citep{rodionov2026ewm} inductively synthesizes executable Python simulators of game transitions, verifies state invariants against historical traces, and performs trajectory search within the simulated model, drawing inspiration from WorldCoder \citep{tang2024worldcoder} and code-based world models \citep{lehrach2025cwm}. Similarly, \emph{Tycho} \citep{lehmann2026tycho} infers programmatic world models, while graph-based exploration frameworks \citep{rudakov2025graph} rank potential actions via visual salience without parameter updates. \emph{VISTA} \citep{vista2026} introduces a multimodal visual harness featuring lossless frame retention. Crucially, all of these systems depend on unbounded, proprietary frontier API endpoints and are evaluated exclusively on the public game distribution, precluding their deployment in offline, resource-bounded environments.

\paragraph{Symbolica's Arcgentica.}
Symbolica's \emph{Arcgentica} \citep{knutsen2026arcgentica} is the closest frontier-API relative of our harness. It is built on the open-source Agentica SDK, which gives each agent a persistent Python REPL and lets it spawn sub-agents that receive only the state they need, instead of the full history. On launch day Symbolica reported an unverified 36.08\% on the 25 public games with Claude Opus~4.6 at high effort, passing 113 of 182 playable levels and fully solving 7 games, at a stated cost of \$1{,}005 \citep{symbolica2026arc3}. The score was not certified by the organizers and Symbolica describes the harness as not specific to ARC-AGI. Arcgentica shares two ideas with \textsc{Sarbloh}: reasoning inside a persistent code environment, and keeping context small. It does so by delegating to sub-agents, whereas we keep one append-only context and drain it deterministically (Section~\ref{sec:method}). Its score is also on the contaminated public games with unbounded API calls, so it is not comparable to a hidden-set offline score.

\paragraph{The Open-Weight Offline Frontier.} 
The direct baseline class for \textsc{Sarbloh} consists of open-weight systems evaluated under the official Kaggle offline protocol (Table~\ref{tab:field}). The Milestone~\#1 benchmark (June 2026) was achieved by Tufa Labs' \emph{Duck} harness \citep{duck2026,arcprizemilestone1}. The Duck framework deploys Qwen~3.6 27B locally within an interactive Python execution environment that exposes environment state variables, ingests observations via composite ASCII grids and visual renderings, and evicts historical context windows to permit continuous execution. Its creators established that rigid, hand-crafted agent toolkits degraded performance compared to flexible, unconstrained code execution. Subsequent second- and third-place systems utilized Gemma-4-31B as a visual action generator predicting JSON-formatted action sequences directly from annotated frames \citep{arcprizemilestone1}. As summarized in Table~\ref{tab:field}, \textsc{Sarbloh} establishes a new state of the art in this offline open-weight domain.
