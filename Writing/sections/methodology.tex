\section{Methodology}
\label{sec:method}

Our initial baseline, adapting the open harness of Prime Agent \citep{karten2026prime}, scored between 0.00 and 0.27 on the hidden evaluation set, initiating over 350 voluntary level restarts across ten games without once resolving a goal state. The reasoning model was proficient at code synthesis, yet fundamentally incapable of spatial scene parsing. This section formalizes the governing principle of representation (Section~\ref{sec:rule}), the deterministic perception engine that realizes it (Section~\ref{sec:perception}), the unified programmatic action interface (Section~\ref{sec:interface}), and the prefix-cached serving loop that fits within single-GPU hardware bounds (Section~\ref{sec:serving}). Figure~\ref{fig:turn} illustrates an end-to-end execution turn of the complete architecture.

\begin{algorithm*}[!t]
\caption{\textsc{Perceive}: one frame to the briefing, the map and the object table}
\label{alg:perceive}
\KwIn{grid $g_t$ ($H{\times}W$, colours 0--15); legal actions $\mathcal{A}$; the level's objects and lattice from the previous frame}
\KwOut{briefing $B$, map $M$, object table $O$, change line $\delta$}
\Stage{1. Objects and their ids (View 1)}
$O \gets$ the 4-connected one-colour regions of $g_t$, background (most common colour) excluded\;
\ForEach{rule in order: (i)~same colour, shape, place; (ii)~same colour, shape, nearest; (iii)~same shape, place; (iv)~same colour, most shared cells}{
  give each still-unmatched object the id of an unmatched previous object that the rule pairs it with\;
}
give every object left unmatched a new id \Comment*[r]{rule (v)}
$\delta \gets$ the cells that changed since the last frame; changes within 3 cells of the edge are reported as HUD\;
\Stage{2. Things on the screen}
$\mathcal{T} \gets$ the colours that cover more than 8\% of $g_t$ \Comment*[r]{terrain}
$L \gets$ the other cells grouped into things: lines, bars, multi-colour composites, icons, dotted figures\;
mark each thing in $L$ as HUD if it is a bar or touches the screen edge, and name it by the id that owns most of its cells\;
$e_{\text{you}} \gets$ the largest multi-colour thing of $\geq 9$ cells off the HUD, squares first \Comment*[r]{likely agent}
$\Lambda \gets$ the side of the largest multi-colour square whose grid matches $>75\%$ of the floor's edges; else the previous lattice, if it still fits\;
\Stage{3. Measured facts: computed by code, stated as fact}
$F \gets$ reach (BFS from $e_{\text{you}}$ on $\Lambda$), enclosures, midpoint tethers, alignments, look-alikes under $D_4{\times}\mathbb{Z}^+$, copies, lopsided colours\;
\Stage{4. Guessed roles: scored, stated as guesses}
\ForEach{thing $e \in L$ that is not a line}{
  add the fixed evidence points of the eight roles (Table~\ref{tab:roles}) that $e$'s shape, place, relations in $F$ and $\mathcal{A}$ earn\;
  $\hat{\rho}_e \gets$ the role with the most points; \quad $p_e \gets \text{its points} \,/\, (\text{all of } e\text{'s points} + 1)$\;
}
\Stage{5. Assemble within $K = 20$ lines}
keep up to $\lfloor K/3 \rfloor$ lines for guesses, each with its one-action test\;
share the other lines among the fact kinds, one line per kind in turn; give guesses any room left over\;
$B \gets$ the chosen facts, then the guesses, then a count of what was left out (``\code{+N more facts}'')\;
$M \gets$ a map of $L$: ids, guessed roles marked ``?'', look-alike threads, tether rings, HUD panel\;
\Return{$B, M, O, \delta$}
\end{algorithm*}

\subsection{The Measured--Guessed Rule}
\label{sec:rule}

We did not start from the rule; a perception lab of nine presentations, graded against an answer key written before any of them ran, produced it (Section~\ref{sec:lab_results}, Figure~\ref{fig:presentations}).

\paragraph{A text-only encoder that states every cell flat scored 3 of 28.}
Initially, our first perception module printed the fitted lattice, a symbol per cell, the palette, connected components and object tracking. Everything it said was correct, but most of the heavy lifting was left to the model itself to identify what each cell represents. It named no agent, no goal and no gauge, and it marked the move counter of \code{r11l} as screen decoration.

\paragraph{Role guesses with tests raised the score to 20, and fusing them with computed relations raised it to 25.}
The Role Ledger scored every object against eight game roles and printed each top guess with its evidence and the cheapest action that would confirm or refute it (20/28, about 380 tokens). The Fused Briefing added the relations that code computes exactly---reachability, enclosure, midpoint tethers, shape equivalence---as a separate tier above the guesses (25/28, about 370 tokens). It scored $8.3\times$ the Legacy Encoder with 89\% fewer tokens. Dumping raw $64\times 64$ ASCII grids alongside per-cell component tables forces the tokenizer to spend $\approx 3{,}500$ tokens per frame encoding repetitive background coordinates; by abstracting connected components on the host, moving spatial layout into the visual Blueprint raster, and emitting only non-redundant geometric relations in text, the Fused Briefing compresses prompt footprint by 89.4\% (to 370 tokens) while increasing prefix-cache capacity by $9.5\times$.

\paragraph{Held-out games separated the two kinds of statement.}
We subsequently evaluated cross-distribution generalization across 23 held-out official game environments excluded during engine prototyping. Grid reconstruction achieved 100\% cell accuracy across all games, and morphological segmentation reliably preserved entity boundaries and spatial tracking without degradation. Whereas topological and geometric invariants hold unconditionally by mathematical construction, high-level semantic roles (such as agent embodiment or interactive affordances) inherently possess visual ambiguity prior to actuation. 
Consequently, the engine treats role labels not as brittle, hardcoded classifications, but as provisional inductive hypotheses paired with minimal unit-action verification probes. This decoupling ensures that any transient misclassification of initial sprite affordances is immediately resolved upon the first interaction step, while preserving complete coordinate, topological, and geometric stability across the entire scene.

\paragraph{The rule.}
\emph{State what can be measured as fact; state what must be inferred as a guess that carries a one-action test.} We term this the \textbf{Measured--Guessed Rule}. A measured relation is computed from the grid by code with no learned parameters, so it is true by construction and the model need not check it. A role cannot be read from one frame, and a role stated as fact plants \emph{perceptual misinduction}---a wrong belief about what an object is or does---that the model then spends actions on. A role stated as a guess with a test costs at most one action to settle, and under RHAE, where cost grows with the square of the action count, that cap is the point.

The rest of this section applies the rule five times. View~1 states object identity across frames as fact (Section~\ref{sec:perception}). 
View~2 states geometric relations as fact. The role scorer states roles as guesses, each with its test (Table~\ref{tab:roles}). View~3 draws both on one map and marks every guessed role with a question mark. Finally, \code{play()} treats the agent's own world model as a guess and checks each of its predictions against the next frame (Section~\ref{sec:interface}).

\subsection{Perception: From Pixels to Stated Facts}
\label{sec:perception}

The engine is the Fused Briefing rewritten to work on the grid inside the agent, with host-side NumPy and Pillow and no learned parameters. On 225 real frames (the first frame and eight random actions on each of 25 offline games) it raised no errors; the briefing took a median of 42\,ms (maximum 0.38\,s) and the picture 40\,ms. Each frame yields three views that share one object-identity space (Figure~\ref{fig:views}). Algorithm~\ref{alg:perceive} gives the whole mapping from grid to views in one place; reading it shows that every learned or heuristic step (role scoring) comes after every exact one.

\paragraph{View 1: re-segmenting each frame renamed objects, so identity is tracked, not recomputed.}
The perception engine identifies the background canvas as the modal color index across the frame and extracts all remaining four-connected monochromatic regions as discrete entities. Because standard morphological segmentation re-indexes components in raster reading order at every step, dynamic entities moving across the board would continually swap indices, causing synthesized Python scripts to silently reference incorrect objects. To maintain temporal consistency, \textsc{Sarbloh} anchors object identifiers on the initial frame of each level and preserves identity across transitions through a multi-stage bipartite matching algorithm. This procedure runs five passes in order: objects unchanged in colour, shape and place; objects moved with the same colour and shape (the nearest is taken); objects recoloured in the same shape and place; objects reshaped in the same colour (the one sharing most cells is taken); and, last, fresh identifiers for objects that match nothing (Algorithm~\ref{alg:perceive}, stage~1). As a result, each identifier reliably tracks the same physical entity throughout an entire level. In addition to the tracked object table, the spatial state is serialized as an alphanumeric coordinate grid and paired with a differential change ledger detailing the bounding box and cell count modified by each transition. Furthermore, environmental modifications occurring within the three-cell peripheral screen boundary are isolated as heads-up display telemetry, preventing passive counter decrements or timer ticks from being misinterpreted as operational task progress.

\paragraph{View 2: a picture does not state relations, so the engine computes them.}
Whether an object can be reached, how many steps it takes, whether a hollow fits another object, or whether two shapes are the same up to rotation cannot be read reliably off a rendered frame \citep{rahmanzadehgervi2024blind}. The engine first splits the frame into \emph{terrain}---colours that cover more than 8\% of the frame---and things (corridors, edge gauges, multi-colour assemblies joined by union-find over 8-connected components, panel icons and dotted figures). It then computes seven kinds of measured fact:
\begin{itemize}
    \item \textbf{Reachability}: breadth-first search over the detected \emph{lattice}---the tile grid the player moves on---gives step counts from the likely agent to every target (``\code{obj 6: reachable in 6 steps}'').
    \item \textbf{Enclosure}: closed outlines around empty space, matched against objects of the same size.
    \item \textbf{Midpoint tethers}: an object held at the midpoint of two others by thin lines, so moving one end moves it (``\code{obj 25 held at midpoint of obj 16 and 36}'').
    \item \textbf{Alignment}: shared rows or columns between objects.
    \item \textbf{Dihedral symmetry}: equality of two shapes under the eight rotations and mirrorings of the square and integer scaling ($D_4 \times \mathbb{Z}^+$), as in ``\code{obj 12 (drawn 2x bigger), mirrored left-right OR turned 90 deg clockwise, becomes exactly obj 4}''.
    \item \textbf{Copies}: identical shapes counted as a set (lives, items).
    \item \textbf{Lopsided colouring}: a symmetric shape with asymmetric colours, which usually marks a direction or a state.
\end{itemize}
In \code{ls20}, the symmetry relation connects the HUD icon to the shape inside the goal enclosure, while in \code{r11l}, tether detection identifies the disc suspended between two handles. The perception lab confirmed that both relationships were discoverable exclusively through these geometric computations (Section~\ref{sec:lab_results}).

\paragraph{Proportional line quotas prevent relation flooding.}
Because pairwise geometric relations like coordinate alignments expand combinatorially in dense scenes (e.g., 792 alignment pairs in \code{bp35}), an unweighted global line cap allows high-frequency alignments to crowd out vital invariants such as symmetries and affordance hypotheses. To maintain structural balance, the briefing scheduler enforces proportional line quotas across invariant categories and reserves up to one-third of the display for candidate role hypotheses, summarizing surplus relations as aggregate counts rather than truncating them (detailed in Appendix~\ref{app:negative_results}).

\paragraph{Roles: the engine guesses what objects are for, and says how to check.}
Non-terrain objects are scored against eight roles with fixed evidence points from game-design priors (Table~\ref{tab:roles}); a role's confidence is its score over the object's total score plus one. Each guess is printed with its one-action test, so a wrong guess costs one action instead of a level.

The briefing shows at most 20 fact and guess lines in the deployed configuration: up to a third for guesses, the rest shared between the fact kinds, with facts about the guessed agent and goal first. The remainder is counted (``\code{+N more facts}'') and stays readable in code through \code{observe().briefing}. Full briefings for the two lab frames are in Appendix~\ref{app:briefings}.

\paragraph{View 3: words go in the text, not in the pixels.}
A small vision encoder reads rendered text unreliably, and a sentence drawn into the image is a sentence the model must transcribe before it can use it. The map therefore carries only short tags (\code{10: YOU?}) that repeat ids from the text, while every sentence travels as text. It draws structure (floor in light tones, walls hatched, the lattice as fine lines, look-alike shapes joined by dashed threads, tethers marked with rings and the HUD magnified in a side panel (Figure~\ref{fig:views}d)).

\paragraph{Observation schedule.}
The full view (briefing, letter grid and map) is sent at the start of a level, after a context drain, and when the agent calls \code{observe()} after acting, at most once per state. After other actions the agent gets the change ledger, a letter crop around the changed cells with a 3-cell margin, and the new map. The object table stays on the host and is read in code (\code{observe().objects}).

\subsection{The Action Interface}
\label{sec:interface}

\paragraph{Separate tools for code and for actions split one plan across many turns.}
In our early builds the agent had one tool to run Python and another to submit moves. In the traces of those builds it modelled the game in one tool, left it to send a single move with the other, and came back to re-derive its state, so one plan cost many turns and every turn cost a model call. We merged the two: the agent acts only from inside its Python kernel, in the CodeAct style \citep{wang2024codeact}, with
\begin{center}
{\small\code{r = await play(path, predict=f)}}
\end{center}
where \code{path} is up to 100 moves and \code{predict} is an optional world model $\hat{f}(s, a) \to \hat{s}$ written by the agent. It is the only change recorded for the build that moved the hidden-set score from 5.14 to 5.65. One cell can now model a level, search it and play the whole path (Figure~\ref{fig:turn}c).

\paragraph{The agent's world model is a guess, so \code{play()} checks it instead of trusting it.}
Algorithm~\ref{alg:play} defines the execution contract between the planned trajectory and the environment, specifying the exact conditions that govern path termination. An inaccurate state prediction does not interrupt execution. Instead, \code{play()} logs the first action whose predicted state differs from the true grid outside the HUD, records the mismatched coordinates, and continues along the trajectory. The path halts only when a level or game terminates, when consecutive identical actions collide with an obstacle without altering a single pixel, or when the revisit guard identifies a board state already visited during the current attempt. The loop never stalls to verify an operational rule, ensuring that any inaccuracies in the internal world model are resolved immediately upon receiving the next frame. Two of the stops are switches. The revisit guard was off in Run~B (briefing on), and the replay guard, which refuses before any move a path that repeats a lost try move for move from the same first board, was on; the saved configuration of Run~A (briefing off) records neither switch.

\begin{algorithm}[!htb]
\caption{\textsc{Play}: sending a planned path and checking the agent's predictions}
\label{alg:play}
\KwIn{path of moves $m_1, \dots, m_K$; optional world model $\hat{f}$ (the agent's \code{step()}); current grid $g_t$}
\KwOut{one change line per move sent, the first surprise (or none), the last grid}
\lIf{$K > 100$}{refuse the whole path; nothing is spent}
\lIf{replay guard on \textbf{and} the path repeats, from the same first board, a try that ended in game over}{refuse it}
$\textit{surprise} \gets$ none\;
\For{$i \gets 1$ \KwTo $K$}{
  \If{$\hat{f}$ given}{
    $\hat{g}_{t+1} \gets \hat{f}(g_t, m_i)$ \Comment*[r]{predict before acting}
    \lIf{$\hat{f}$ raised an error}{stop; $m_i$ is not sent}
  }
  send $m_i$; read the new grid $g_{t+1}$ \Comment*[r]{the move is spent}
  \If{$\hat{f}$ given \textbf{and} no surprise yet \textbf{and} $\hat{g}_{t+1}$ differs from $g_{t+1}$ outside the HUD}{
    $\textit{surprise} \gets (i,\, m_i,\, \text{the differing cells})$ \Comment*[r]{reported; the path goes on}
  }
  \lIf{the level was won \textbf{or} the game is over}{stop}
  \lIf{$m_i$ changed nothing \textbf{and} the move before it was $m_i$ and also changed nothing}{stop (a wall hit twice)}
  \lIf{revisit guard on \textbf{and} $g_{t+1}$ was already seen in this try}{stop}
  $t \gets t + 1$\;
}
\Return{the change lines, \textit{surprise}, $g_t$}
\end{algorithm}

\paragraph{Revisit guard behavior under live deployment.}
The revisit guard terminates path execution whenever the non-HUD board configuration repeats a state encountered earlier in the attempt. In counterfactual analysis over 9,913 actions, the guard identified 2,331 duplicate states (with a minor false-positive cost of 6 winning transitions). Under live deployment, when interrupted by the guard, reasoning models compensated by increasing single-action invocations from 8.9\% to 17.8\% and dispatching subsequent moves in the same cell, shifting completed levels marginally from 50 to 52 out of 97. We retain the guard as a configurable safeguard while noting that visible execution constraints can induce compensatory behaviors in reasoning backbones.

\subsection{Serving Inside the Envelope}
\label{sec:serving}

\paragraph{Append-only context invariant preserves prefix-cache reuse.}
We deploy our 125B MoE backbone quantized to W4A16 using AutoRound \citep{cheng2023autoround} and served via SGLang \citep{zheng2023sglang} with EAGLE speculative decoding \citep{li2024eagle}. The model architecture mixes Gated DeltaNet linear-recurrent layers with attention \citep{yang2024gated}. Its recurrent state cannot be rewound, so the server can resume only from the state saved at the end of an earlier request, and the prefix cache matches nothing past the first modified token. To guarantee cache reuse, we enforce an \emph{append-only} invariant: every request is the previous request plus its reply and new messages, word for word. Visual maps are retained across turns, reasoning remains in history, and working memory updates append as new lines. A game retains its GPU slot for 20 requests before scheduling handoff. Across our full benchmark run, 98.4\% of 1.78\,B prompt tokens were served directly from cache, reducing prefill to 1.3\% of busy time and rendering execution decode-bound (Figure~\ref{fig:cache}).

\paragraph{Deterministic context drainage eliminates hallucinated summaries.}
Harnesses that compact context typically invoke an LLM to generate summaries \citep{knutsen2026arcgentica}, which costs shared GPU cycles and risks hallucinating persistent false facts into context history. Our context drain operates entirely without model inference: when context exceeds 118k tokens, it deterministically drops the oldest complete turns until history falls below 55k tokens. The system prompt remains pinned, unevicted turns are preserved verbatim, and the symbolic memory store and code graph are re-anchored as a single deterministic block.

\paragraph{Kernel working memory and priority scheduling.}
The agent maintains four level-keyed symbolic dictionaries in the Python kernel (\code{GOAL}, \code{PLAN}, \code{HYPOTHESES}, \code{FINDINGS}) that persist across context drains and level transitions. Upon level completion, a curator call consolidates confirmed mechanics into a persistent \code{SKILLS} repository and registers refuted rules to prevent redundant exploration. Across 25 concurrent games, an asynchronous priority scheduler allocates 10 active GPU slots based on level reward weight discounted by committed actions, multiplying by a decay factor that prevents stalled games from starving progressing ones (Appendix~\ref{app:scheduler}).

\paragraph{Ablated designs and boundary conditions.}
Across our development cycle, several architectural alternatives proved detrimental or inert. Replacing past code with semantic stubs caused 6B models to degenerate into copying comment templates in 97.7\% of calls, fine-tuning on self-generated successful traces reduced training loss while degrading interactive generalization, and spawning autonomous subagents introduced coordination overhead without performance gain. A complete analysis of these ablated designs and runtime edge cases is provided in Appendix~\ref{app:negative_results}.
