\section{Methodology}
\label{sec:method}

Our first agent, a port of Prime Agent \citep{karten2026prime}, scored 0.00 to 0.27 on the hidden set and restarted levels more than 350 times in ten games without once finding a goal. The model could write code. It could not tell what it was looking at. This section rebuilds the agent around one rule for what the model is told about a frame (Section~\ref{sec:rule}), the engine that applies it (Section~\ref{sec:perception}), what broke when that engine met live play (Section~\ref{sec:broke}), the interface through which the agent acts (Section~\ref{sec:interface}), the serving loop that keeps all of it inside one GPU (Section~\ref{sec:serving}) and the designs we tried and dropped (Section~\ref{sec:rejected}). Figure~\ref{fig:turn} shows one real turn of the finished system.

\subsection{The Measured--Guessed Rule}
\label{sec:rule}

We did not start from the rule; a perception lab of nine presentations, graded against an answer key written before any of them ran, produced it (Appendix~\ref{app:lab}, Figure~\ref{fig:presentations}).

\paragraph{A text-only encoder that states every cell flat scored 3 of 28.}
In the beggining our first perception module printed the fitted lattice, a symbol per cell, the palette, connected components and object tracking. Everything it said was correct but, most of the heavy lifting was done by the model itself as the model has to identify what each cell represents. It named no agent, no goal and no gauge, and it marked the move counter of \code{r11l} as screen decoration.
\paragraph{Role guesses with tests raised the score to 20, and fusing them with computed relations raised it to 25.}
The Role Ledger scored every object against eight game roles and printed each top guess with its evidence and the cheapest action that would confirm or refute it (20/28, about 380 tokens). The Fused Briefing added the relations that code computes exactly---reachability, enclosure, midpoint tethers, shape equivalence---as a separate tier above the guesses (25/28, about 370 tokens). It scored $8.3\times$ the Legacy Encoder with 89\% fewer tokens.

\paragraph{Held-out games separated the two kinds of statement.}
We subsequently evaluated cross-distribution generalization across 23 held-out official game environments excluded during engine prototyping. the grid reconstruction was able to achieve 100\% cell accuracy across all games, and morphological segmentation reliably preserved entity boundaries and spatial tracking without degradation. Whereas topological and geometric invariants hold unconditionally by mathematical construction, high-level semantic roles (such as agent embodiment or interactive affordances) inherently possess visual ambiguity prior to actuation. 
Consequently, the engine treats role labels not as brittle, hardcoded classifications, but as provisional inductive hypotheses paired with minimal unit-action verification probes. This decoupling ensures that any transient misclassification of initial sprite affordances is immediately resolved upon the first interaction step, while preserving complete coordinate, topological, and geometric stability across the entire scene.

\paragraph{The rule.}
\emph{State what can be measured as fact; state what must be inferred as a guess that carries a one-action test.} We term this the \textbf{Measured--Guessed Rule}. A measured relation is computed from the grid by code with no learned parameters, so it is true by construction and the model need not check it. A role cannot be read from one frame, and a role stated as fact plants \emph{perceptual misinduction}---a wrong belief about what an object is or does---that the model then spends actions on. A role stated as a guess with a test costs at most one action to settle, and under RHAE, where cost grows with the square of the action count, that cap is the point.

The rest of this section applies the rule five times. View~1 states object identity across frames as fact (Section~\ref{sec:perception}). 
View~2 states geometric relations as fact. The role scorer states roles as guesses, each with its test (Table~\ref{tab:roles}). View~3 draws both on one map and marks every guessed role with a question mark. Finally, \code{play()} treats the agent's own world model as a guess and checks each of its predictions against the next frame (Section~\ref{sec:interface}).

\subsection{Perception: From Pixels to Stated Facts}
\label{sec:perception}

The engine is the Fused Briefing rewritten to work on the grid inside the agent, with host-side NumPy and Pillow and no learned parameters. On 225 real frames (the first frame and eight random actions on each of 25 offline games) it raised no errors; the briefing took a median of 42\,ms (maximum 0.38\,s) and the picture 40\,ms. Each frame yields three views that share one object-identity space (Figure~\ref{fig:views}). Algorithm~\ref{alg:perceive} gives the whole mapping from grid to views in one place; reading it shows that every learned or heuristic step (role scoring) comes after every exact one.

(c, d)~The engine's maps for the opening frames of \code{ls20} (arrow keys) and \code{r11l} (clicks): floor in light tones, walls hatched, the HUD moved to a side panel, every object tagged with its id and guessed role (\code{id: ROLE?}). \paragraph{View 1: re-segmenting each frame renamed objects, so identity is tracked, not recomputed.}
The perception engine identifies the background canvas as the modal color index across the frame and extracts all remaining four-connected monochromatic 
regions as discrete entities because standard morphological segmentation re-indexes components in raster reading order at every step, dynamic entities moving across the board would continually swap indices, causing synthesized Python scripts to silently reference incorrect objects. To maintain temporal consistency, \textsc{Sarbloh} anchors object identifiers on the initial frame of each level and preserves identity across transitions through a multi-stage bipartite matching algorithm. This procedure sequentially matches entities based on rigid spatial invariance, spatial translation with identical geometry, chromatic state updates with stationary coordinates, and topological overlap exceeding fifty percent for deformable structures, assigning fresh identifiers only to newly instantiated components. As a result, each identifier reliably tracks the same physical entity throughout an entire level. In addition to the tracked object table, the spatial state is serialized as an alphanumeric coordinate grid and paired with a differential change ledger detailing the bounding box and cell count modified by each transition. Furthermore, environmental modifications occurring within the three-cell peripheral screen boundary are isolated as heads-up display telemetry, preventing passive counter decrements or timer ticks from being misinterpreted as operational task progress.

\paragraph{View 2: a picture does not state relations, so the engine computes them.}
Whether an object can be reached, how many steps it takes, whether a hollow fits another object, or whether two shapes are the same up to rotation cannot be read reliably off a rendered frame \citep{rahmanzadehgervi2024blind}. The engine first splits the frame into \emph{terrain}---colours that cover more than 8\% of the frame---and things (corridors, edge gauges, multi-colour assemblies joined by union-find over 8-connected components, panel icons and dotted figures). It then computes seven kinds of measured fact:
\begin{itemize}
    \item \textbf{Reachability}: breadth-first search over the detected \emph{lattice}---the tile grid the player moves on---gives step counts from the likely agent to every target (``\code{obj 6: reachable in 6 steps}'').
    \item \textbf{Enclosure}: closed outlines around empty space, matched against objects of the same size.
    \item \textbf{Midpoint tethers}: an object held at the midpoint of two others by thin lines, so moving one end moves it (``\code{obj 25 held at midpoint of obj 16 and 36}'').
    \item \textbf{Alignment}: shared rows or columns between objects.
    \item \textbf{Dihedral symmetry}: equality of two shapes under the eight rotations and mirrorings of the square and integer scaling ($D_4 \times \mathbb{Z}^+$), as in ``\code{obj 12 (drawn 2x bigger), mirrored left-right OR turned 90 deg clockwise, becomes exactly obj 4}''.
    \item \textbf{Copies}: identical shapes counted as a set (lives, items).
    \item \textbf{Lopsided colouring}: a symmetric shape with asymmetric colours, which usually marks a direction or a state.
\end{itemize}
In \code{ls20}, the symmetry relation connects the HUD icon to the shape inside the goal enclosure, while in \code{r11l}, tether detection identifies the disc suspended between two handles. The perception lab confirmed that both relationships were discoverable exclusively through these geometric computations (Appendix~\ref{sec:lab-results}).

\paragraph{Roles: the engine guesses what objects are for, and says how to check.}
Non-terrain objects are scored against eight roles with fixed evidence points from game-design priors (Table~\ref{tab:roles}); a role's confidence is its score over the object's total score plus one. Each guess is printed with its one-action test, so a wrong guess costs one action instead of a level.

The briefing shows at most 20 fact and guess lines in the deployed configuration (30 in the build of Section~\ref{sec:broke}): up to a third for guesses, the rest shared between the fact kinds, with facts about the guessed agent and goal first. The remainder is counted (``\code{+N more facts}'') and stays readable in code through \code{observe().briefing} (Section~\ref{sec:broke} explains why the lines are shared). Full briefings for the two lab frames are in Appendix~\ref{app:briefings}.

\paragraph{View 3: words go in the text, not in the pixels.}
A small vision encoder reads rendered text unreliably, and a sentence drawn into the image is a sentence the model must transcribe before it can use it. The map therefore carries only short tags (\code{10: YOU?}) that repeat ids from the text, while every sentence travels as text. It draws structure (floor in light tones, walls hatched, the lattice as fine lines, look-alike shapes joined by dashed threads, tethers marked with rings and the HUD magnified in a side panel (Figure~\ref{fig:views}c,d)).

\paragraph{Observation schedule.}
The full view (briefing, letter grid and map) is sent at the start of a level, after a context drain, and when the agent calls \code{observe()} after acting, at most once per state. After other actions the agent gets the change ledger, a letter crop around the changed cells with a 3-cell margin, and the new map. The object table stays on the host and is read in code (\code{observe().objects}).

\begin{algorithm}[t]
\caption{\textsc{Perceive}: one frame to three views}
\label{alg:perceive}
\KwIn{Grid $g_t \in \{0..15\}^{H\times W}$, tracker $T$, previous lattice $\Lambda'$, legal actions $\mathcal{A}$}
\KwOut{Briefing $B$, tracked objects $O$, map $M$, change ledger $\delta$}
$O \gets \textsc{Segment}(g_t)$\;
$(O, \delta) \gets T.\textsc{Match}(O)$ \Comment*[r]{five passes; ids fixed per level}
$\mathcal{T} \gets \{c \in \{0..15\} : |g_t{=}c| > 0.08\,HW\}$ \Comment*[r]{terrain}
$L \gets \textsc{Layout}(g_t, \mathcal{T})$\;
\ForEach{thing $e \in L$}{
  $e.\mathit{hud} \gets \textsc{AtScreenEdge}(e)$; \quad $e.\mathit{id} \gets \textsc{MajorityId}(e, O)$\;
}
$e_{\text{you}} \gets \textsc{LikelyAgent}(L, \mathcal{A})$\;
$\Lambda \gets \textsc{DetectLattice}(L \setminus \text{HUD}) \textbf{ or } \Lambda'$ \Comment*[r]{keep last lattice if it fits}
$F \gets \textsc{Reach}(e_{\text{you}}, \Lambda) \cup \textsc{Enclosures}(L) \cup \textsc{Tethers}(L) \cup \textsc{Symmetries}_{D_4\times\mathbb{Z}^+}(L)$ \Comment*[r]{measured}
\ForEach{thing $e \in L$}{
  $\boldsymbol{\sigma}_e \gets \textsc{ScoreRoles}(e, F, \mathcal{A})$; \quad $\hat{\rho}_e \gets \arg\max_r \boldsymbol{\sigma}_e[r]$\;
  $p_e \gets \boldsymbol{\sigma}_e[\hat{\rho}_e] / (1 + \sum_r \boldsymbol{\sigma}_e[r])$ \Comment*[r]{guessed}
}
$B \gets \textsc{Facts}(F) \,\|\, \textsc{Guesses}(\hat{\boldsymbol{\rho}}, \boldsymbol{p}, \textsc{Tests}(\hat{\boldsymbol{\rho}}))$\;
$M \gets \textsc{DrawMap}(L, \hat{\boldsymbol{\rho}}, F)$\;
\Return{$B, O, M, \delta$}
\end{algorithm}

The engine states facts correctly on the frames it was designed on, and its guesses are honest about being guesses.
However, the engine was engineered basd on the dynamics(geometry, topology, etc.) observed in public games, and it is not a learned model. 
It does not generalize perfectly to unseen games or to frames from live play.

\subsection{What Broke Under Live Play}
\label{sec:broke}

\paragraph{The lattice test flipped between frames, so reachability facts appeared and vanished mid-level.}
On \code{ls20} the engine lost its $5{\times}5$ tile grid after one move, because the gauge in the status box added edges that lie off the grid; on \code{ka59} it lost its $3{\times}3$ grid whenever the player touched another object. Each flip deleted every reachability fact from the briefing, so the agent was told on one frame that the goal was 5 steps away and on the next frame nothing. We now leave status boxes out of the lattice test and keep the level's previous lattice while it still fits the frame. On the same 225 frames this removed every flip. A fact that is true by construction is only true if its inputs are the right inputs.

\paragraph{Alignment facts crowded out every other kind when the briefing had a single cap.}
In scenes containing numerous entities, pairwise coordinate alignments expand combinatorially. For example, the initial frame of \code{tr87} yields 60 alignment relations compared to only 7 enclosure relations and 1 symmetry relation, while \code{bp35} produces 792 alignment pairs. Under an unweighted global line cap, these high-frequency alignment facts quickly saturate the briefing, crowding out sparse but vital invariants such as symmetry relations and operational role hypotheses (Figure~\ref{fig:budget}a). To prevent dominant relation categories from monopolizing the observation space without discarding structural information, the briefing scheduler allocates line quotas proportionally across invariant types and reserves up to one-third of the total display for affordance hypotheses. This balanced sharing policy ensures that critical geometric symmetries and candidate roles remain visible in context, while surplus relations are summarized as aggregate counts rather than silently truncated (Figure~\ref{fig:budget}b).

\subsection{The Action Interface}
\label{sec:interface}

\paragraph{Separate tools for code and for actions split one plan across many turns.}
In our early builds the agent had one tool to run Python and another to submit moves. In the traces of those builds it modelled the game in one tool, left it to send a single move with the other, and came back to re-derive its state, so one plan cost many turns and every turn cost a model call. We merged the two: the agent acts only from inside its Python kernel, in the CodeAct style \citep{wang2024codeact}, with
\begin{center}
{\small\code{r = await play(path, predict=f)}}
\end{center}
where \code{path} is up to 100 moves and \code{predict} is an optional world model $\hat{f}(s, a) \to \hat{s}$ written by the agent. It is the only change recorded for the build that moved the hidden-set score from 5.14 to 5.65. One cell can now model a level, search it and play the whole path (Figure~\ref{fig:turn}c).

\paragraph{The agent's world model is a guess, so \code{play()} checks it instead of trusting it.}
Algorithm~\ref{alg:play} defines the execution contract between the planned trajectory and the environment, specifying the exact conditions that govern path termination. An inaccurate state prediction does not interrupt execution. Instead, \code{play()} logs the first action whose predicted state differs from the true grid outside the HUD, records the mismatched coordinates, and continues along the trajectory. The path halts only when a level or game terminates, when consecutive identical actions collide with an obstacle without altering a single pixel, or when the revisit guard identifies a board state already visited during the current attempt. The loop never stalls to verify an operational rule, ensuring that any inaccuracies in the internal world model are resolved immediately upon receiving the next frame.


\begin{algorithm}[t]
\caption{\textsc{Play}: running a planned path}
\label{alg:play}
\KwIn{Moves $m_1, \dots, m_K$ ($K \le 100$), optional world model $\hat{f}$}
$s \gets \textsc{Observe}()$; \quad $\textit{surprise} \gets \varnothing$\;
\For{$i \gets 1$ \KwTo $K$}{
  \lIf{$\hat{f} \neq \varnothing$}{$\hat{s} \gets \hat{f}(s.\text{board}, m_i)$}
  $\textsc{Host}.\textsc{Act}(m_i)$; \quad $s' \gets \textsc{Observe}()$ \Comment*[r]{the move is spent}
  \If{$\hat{f} \neq \varnothing$ \textbf{and} $\textit{surprise} = \varnothing$ \textbf{and} $\textsc{Diff}_{\neg\text{HUD}}(\hat{s}, s'.\text{board}) \neq \varnothing$}{
    $\textit{surprise} \gets (i, m_i, \text{differing cells})$ \Comment*[r]{reported, not fatal}
  }
  \If{level won \textbf{or} game over \textbf{or} wall hit twice \textbf{or} ($s'$ seen in this attempt \textbf{and} guard on)}{
    \textbf{break}\;
  }
  $s \gets s'$\;
}
\Return{change ledgers, \textit{surprise}, $s'$}
\end{algorithm}

\paragraph{A revisit guard looked free offline and was routed around live.}
The \emph{revisit guard} terminates path execution whenever the board state, excluding the peripheral three-cell HUD border, repeats a configuration visited earlier within the same attempt. In an offline counterfactual analysis across a 13-game run from 26~October, the guard would have pruned 2{,}331 of 9{,}913 exploratory actions, though six of those were valid winning transitions, demonstrating a measurable false-positive cost. During live deployment, the guard triggered 1{,}814 times, prompting the agent to actively circumvent the constraint by increasing single-action \code{play()} invocations from 8.9% to 17.8% of total actions and dispatching 22% of subsequent moves within the same execution cell after being halted. Consequently, level completions shifted only marginally from 50 to 52 out of 97, a difference within expected run-to-run variance. We retain the guard as a configurable option without claiming an empirical performance advantage, noting that deterministic execution constraints visible in context can induce compensatory gaming behaviors in reasoning models.

While this programmatic interface minimizes physical action expenditure, it does not reduce the computational cost of inference. With 25 concurrent games sharing a single GPU, the primary operational bottleneck shifts to the model serving loop.

\subsection{Serving Inside the Envelope}
\label{sec:serving}

\paragraph{Rewriting the end of the prompt destroyed prefix-cache reuse on a recurrent backbone.}
Our backbone mixes Gated DeltaNet linear-recurrent layers with attention \citep{yang2024gated}. Its recurrent state cannot be rewound, so the server can resume only from the state saved at the end of an earlier request, and the \emph{prefix cache}---the server's store of already-processed prompt prefixes---matches nothing past the first changed token. In the build of 19~October the board picture was sent as the last message of each request and never stored, and each game gave up its GPU slot at every turn end. Of 960 requests, 959 reused exactly the 4{,}416 pre-warmed system-prompt tokens and prefilled everything after them again: 10.5\% of prompt tokens came from cache, and the median turn took 58\,s (Figure~\ref{fig:cache}).

\begin{figure}[t]
\centering
\includegraphics[width=\columnwidth]{figures/cache_curve.pdf}
\caption{Share of each request's prompt tokens served from the prefix cache (moving mean over 25 requests), for the first 960 requests of two Qwen3.8-Flash-Next runs on SGLang. Before (19~October, 15 games): the picture is the unstored last message and the GPU slot changes hands every turn. After (23~October, 25 games): every request is the previous request plus its reply, and a game keeps its slot for 20 requests. Labels on the right give the whole run.}
\label{fig:cache}
\end{figure}

We now enforce an \emph{append-only} invariant: every request is the previous request plus its reply and new messages, word for word. Pictures are stored as messages once per new state and kept, reasoning stays in the history, and memory changes are appended as new lines. A game keeps its slot for 20 requests before the scheduler may hand it over, so at most about one request in 20 starts cold. Over the 8.2-hour run of 23~October, 98.4\% of 1.78\,B prompt tokens came from cache and prefill took 1.3\% of the busy time, against 50.1\% for decoding (Table~\ref{tab:telemetry}). The run is decode-bound.

\paragraph{Summarising old context costs a model call and can invent facts, so we drain it instead.}
Harnesses that compact context ask a model to summarise it \citep{knutsen2026arcgentica}. The summary is model output: it costs a call on the shared GPU and can carry a fact that was never on the board into every later turn. Our \emph{context drain} uses no model at all. When the context passes 118k tokens it drops the oldest whole turns until it is under 55k; everything that remains is word for word what the model saw, the system prompt stays pinned, and the memory and code graph are put back as one block. A drain costs one cold prefill and introduces nothing.

\paragraph{Working memory lives in the kernel, so it survives drains and level changes.}
The agent keeps four Python dictionaries in its kernel---\code{GOAL}, \code{PLAN}, \code{HYPOTHESES} and \code{FINDINGS}---keyed by level and kept across level changes. After each cleared level one curator call turns the level's confirmed and refuted hypotheses into a fifth store, \code{SKILLS}, and a list of refuted rules that are not proposed again (143 curator calls and 339 skills in the 23~October run). After each cell a static code graph appends one line naming the functions the cell defined or broke.

\paragraph{The scheduler gives the GPU to the game most likely to score next.}
All 25 games start at once and share 10 GPU slots. A game's priority is the RHAE weight of its current level, discounted by the actions it has already spent there, plus a small value for the levels it would unlock, times a \emph{hope} term that halves as tokens and actions spent on the level without a win grow (Appendix~\ref{app:scheduler}). Games that stall lose the GPU to games that progress, and a game that clears a level starts again at full priority. The constants are set by hand and not tuned.

\paragraph{Model and runtime.}
We serve Qwen3.8-Flash-Next, a 125B-parameter mixture of experts with 6B active parameters per token, quantised to W4A16 with AutoRound \citep{cheng2023autoround} and served by SGLang \citep{zheng2024sglang} with EAGLE speculative decoding \citep{li2024eagle} (3 draft tokens), an FP8 KV cache and a 136k context. Each reply is capped at 12k tokens and each game at 400 turns. A watchdog restarts a server whose token counters stop moving while requests are open, within the wall-clock budget left.

\subsection{Rejected Designs}
\label{sec:rejected}

\paragraph{Sparse deltas.}
We sent only the cells that changed after each action. Actions in these games often change distant cells---stepping on a tile in \code{ls20} changes an icon in the status panel---and with local updates only, the agent missed the coupling and concluded its action did nothing (Section~\ref{sec:motivation}). Change must be reported against the whole frame, with the HUD split out, never instead of it.

\paragraph{Split tools.}
Separate tools for running code and for sending moves made the agent leave its own model to act and return to rebuild it. Merging them into \code{await play()} is the only recorded change between hidden-set scores of 5.14 and 5.65. An agent that plans in code must also act in code.

\paragraph{History stubbing.}
To save tokens we replaced the agent's past code in the context with a short comment. The model copied the comment as its next cell instead of writing code: in 1{,}855 of 2{,}088 calls on 16~October, and in 8{,}242 of 8{,}438 calls (97.7\%) on 25~October, which cleared 0 of 97 levels. A 6B-active model imitates its own history, so anything placed where its code goes must be real code.

\paragraph{Subagents.}
The Prime Agent harness offers a call that spawns subagents. Across our first three Prime experiments and a 10-game autopsy, the open-weight models spawned none, while the port scored 0.00 to 0.27 (Section~\ref{sec:trajectory}). We run one agent per game, with one curator call between levels; delegation the model never uses is complexity without benefit.

\paragraph{Fine-tuning on our own traces.}
A LoRA fine-tune on traces of cleared levels lowered the training loss from about 11\% to about 6\%, and the tuned model played worse; it used about 80\% of our training compute. We did not find the cause. Lower imitation loss is not better play, and under a fixed compute budget the harness was the better place to spend it.
