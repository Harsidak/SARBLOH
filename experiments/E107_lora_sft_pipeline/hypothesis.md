## Mechanism

`sft/lora_sft.py` is a single file that needs only torch, transformers and peft, with no TRL. It:
1. Validates the conversations. It accepts plain chat rows and Prime `sft_levels.jsonl` rows.
2. Renders them with the model's own chat template.
3. Masks the loss to the assistant tokens. A whole render is used when the template is prefix-stable. Otherwise
   there is one example per assistant turn.
4. Loads the declared architecture class (`Qwen3_5ForConditionalGeneration`). Any missing weight that is not on
   the allow-list is a hard failure.
5. Puts LoRA on the language model's linear layers only, never the vision tower.
6. Trains with plain torch.
7. Evaluates before and after: loss on target tokens, token accuracy, and greedy generations.
8. Saves the adapter.
9. Reloads the adapter into a fresh base and requires the same eval loss.
10. Writes `result_card.{json,md}`, `loss.png` and `train.log`, with a PASS/FAIL verdict.

The Kaggle launcher is `kaggle/experimental/sft_smoke.ipynb`, generated by `sft/make_notebook.py`. It is pushed with
`scripts/kaggle_push.py sft`, which embeds the working tree's sources. Settings: Qwen/Qwen3.5-2B (the same qwen3_5
family and template as Qwen3.8-27B), a T4 with internet on, fp32 (T4 has no bf16), LoRA r=16, lr 5e-4, 40 steps.

## Why it should work

Three samples with 681 target tokens, at 40 steps and r=16, are easy to memorise. If the masks, the gradient path,
the saving and the reloading are right, the eval loss collapses and the generations reproduce the references. If
any one of them is wrong, a check names it.

## Prediction

Committed before the Kaggle run:
- Verdict PASS, with every check green.
- Eval loss drops by 50% or more. The local CPU run on a tiny random model only showed that the loss moves.
- The reloaded adapter matches within 2%.
- After training, the generations match the reference tool names.
- Wall clock under 30 minutes on a T4.

## Kill criterion

Kill (and fix before any real SFT) if any of these happen:
- The verdict is FAIL for a reason other than the loss-drop threshold.
- The reloaded loss differs from the post-training loss.
- Any weight outside the allow-list is missing when the checkpoint loads.

## Measurement

`result_card.json` from the kernel output (`scripts/kaggle_push.py sft-output`). Record: the checks, loss
before/after/reloaded, train seconds, peak VRAM, and generation similarity.
